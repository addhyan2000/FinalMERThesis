### Single-section keys — the shortening risk

`liong2014a`, `liong2014b`, `xu2017`, `ben2021`, `lu2015`, `liY2018`, `liY2021`, `zhang2022`, `davison2018`, `zhaoG2007`, `liong2018` appear in **one section each**. Either keep one citing sentence or remove the bibliography entry deliberately.

**`liong2018` is cited exactly once in Chapter 3** (§3.1) and once in Chapter 5's Table 5.8. It is the most fragile key in the chapter.

### Citation numbering trap

`tools/bibliography.py` assigns reference numbers **by first appearance across the whole thesis**, with Chapter 1 registered first in `THESIS_ORDER`. Cutting the *first* occurrence of a key in Chapter 3 shifts that key's number if its next occurrence falls in a later chapter — which renumbers the reference list and every chapter's rendered citations. After any cut, rebuild all six chapters and re-run the check; a silent renumber is the failure mode that will not announce itself.

## 6. The subagent method

`SUBAGENT_WORKFLOW.md` is the method and it still holds. What this session added:

**Three agents at a time, report-only, controller applies every fix.** Agents that edit produce silent changes you cannot weigh. Every audit this session was read-only; every edit was made by the controller after verifying the finding.

**Write reports incrementally.** Four agents died to rate limits this session. Those instructed to create the report file first and append per section lost nothing; those that held findings in memory lost everything. Put this in every brief:

> Create the report file immediately, before analysis, and append each section's findings the moment you finish that section. Never hold findings in memory to write at the end.

**Pre-extract the PDFs.** `pdftotext -layout docs/<file>.pdf scratchpad/txt/<key>.txt` for all 27 keys, once, before dispatching. Agents then read text instead of re-extracting, and the same cache serves every wave. **But:** the text layer mangles equations routinely. Any brief touching §3.4 or §3.7 must say *render the page as an image with the Read tool's `pages` parameter before concluding anything about a formula*.

**Precompute the numbers.** For any chapter making numeric claims, compute the ground truth by script first and hand it to the agents rather than letting each recompute. It eliminates an entire class of disagreement.

**The three instructions that earn their place in every brief:**

> Before writing "no concerns", run a check that would disprove it. Name that check in your report.

> If any number in this brief is contradicted by the source data, do not write it — report the discrepancy instead.

> This chapter is already fact-audited. Any factual change is a defect, **including one that looks like a correction**. If you believe a fact is wrong, report it; do not fix it.

**Briefs are not a trusted source.** Agents corrected the controller's briefs repeatedly this session — a stale lead about Table 3.12, a wrong section number for the no-hyperparameter-search limitation, two repetition leads that did not hold. That is the instruction working.

**Check every finding before acting.** Roughly two in twenty-five are wrong in either direction. This session rejected three confirmed-looking findings: a claim that the u-channel negation was broken (the subsequent z-score restores the sign flip exactly), a claim that `MetricsComputer` was a ghost reference (it exists; the attribution was wrong), and a recomputation of the always-Negative floor (the thesis was right). Open the file, run the arithmetic.

**Rate limits.** Opus and Sonnet have separate capacity and separate reset times. When one is exhausted, dispatch on the other. A dead agent is not necessarily lost work — check the filesystem before re-dispatching.

**What the scripts catch:** a `§x.y` that does not resolve, a `Table n.m` or `Figure n.m` that does not exist, an unknown citation key, an orphaned bibliography entry, a residual author–year string.

**What they cannot catch, and what therefore needs a reader:**

- A cross-reference that resolves to a real heading but **misdescribes what is there**. Cutting content is the commonest way to create these — §3.2.6 ended "§3.2.7 records the numbers" after the numbers had been removed from §3.2.7.
- A **heading that outruns its body**. This session found three: §3.4.6's "Every strain method…", §3.5.4's "The one systematic comparison" above a body saying "the second", §3.10.2(a)'s "No component is ever isolated". Headings are what a skimming examiner reads. Judge them separately.
- A **gap claim** that has become false, or was always false.
- A fact that now exists **nowhere**, because both statements of it were treated as duplicates.
